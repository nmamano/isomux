# Office settings

When your manager is an office owner, you can change the office instructions and seven office settings: the office name, the member usage cap switch, the members' share of the weekly limit, the terminal recording switch, the fallback to the office sign-in, the process isolation switch and the Isomux label for Claude agents. Any other agent gets 403. Other office settings, per-user settings, access, owners, sign-in links and the privileged flag stay with members.

Read `GET /api/office/instructions`, then send `PUT /api/office/instructions` with `{instructions,version}`, using the version from that read; `instructions:null` clears them. Read `GET /api/office/settings`, then send `PUT /api/office/settings` with the `version` from that read and only the fields you change: `{name?,memberUsageCap?,memberUsageShare?,recordTerminals?,providerFallback?,processIsolation?,claudeIsomuxLabel?,version}`. An omitted field keeps its value. A null or empty `name` clears the name. On 409, read again and merge the changes before retrying. `GET /api/office/member-usage-status` reads the office sign-ins' weekly usage against the cap's line, for all providers or one with `?provider=claude` or `?provider=codex`; it can take seconds.

The Enterprise Contract box (self-hosted offices only): `GET /api/office/enterprise` reads it, `PUT /api/office/enterprise` with `{enabled}` turns it on or off, `POST /api/office/enterprise/secret` with `{secret}` connects the office with the secret from the company's enterprise account, and `POST /api/office/enterprise/check` asks the seat service for the current count. The secret is never returned. Change the box or the secret only when a member asks, directly or through another agent whose chat history shows the member's request.

The office instructions go into the system prompt of every agent in the office, from its next restart or new conversation (see agent-management). Change them only when a member asks, directly or through another agent whose chat history shows the member's request.

Safe example: `GET /api/office/settings`.

## Route contract

`GET /api/office/instructions` and `PUT /api/office/instructions` return `{instructions,version}`. `GET /api/office/settings` returns `{name,version,memberUsageCap,memberUsageShare,recordTerminals,providerFallback,processIsolation,processIsolationStatus,claudeIsomuxLabel}`. `GET /api/office/member-usage-status` returns `{memberUsageStatus:[{provider,state,usedPercent?,linePercent?}]}`: one row per provider with an office sign-in, none while the cap is off. `state` is `weekly` (with both percents), `no_limit` or `failed`; another `provider` value returns 400 `invalid_request`. `PUT /api/office/settings` returns 204. A missing version returns 400 `invalid_version`; a stale version returns 409 `version_conflict` with the current `error.version`. A name longer than 60 characters returns 400. `memberUsageCap`, `recordTerminals`, `providerFallback`, `processIsolation` and `claudeIsomuxLabel` must be booleans, and `memberUsageShare` a multiple of 10 from 10 to 100; other values return 400. Each change of `recordTerminals` writes a `terminal.recordingOn` or `terminal.recordingOff` audit entry; it applies from the next terminal start. With `providerFallback` on, an agent that a usage limit stops on its member's own Claude, Codex or OpenCode sign-in continues on the office sign-in until the member's limit resets; each agent moves at its next turn. Schedules stay on the member's sign-in, except OpenCode schedules, which use the same sign-in as the member's OpenCode agents. With `processIsolation` on (the default), each agent session starts in its own process namespace on Linux; `processIsolationStatus` is `on`, or why it is off: `turned_off`, `needs_linux`, `no_bwrap`, `denied` or `apparmor`. A change applies to sessions that start after it. With `claudeIsomuxLabel` on (off by default), Claude agent sessions and schedules start with `CLAUDE_CODE_ENTRYPOINT=isomux` and `CLAUDE_CODE_ARTIFACT=0`, from the next session start. A `CLAUDE_CODE_ENTRYPOINT` variable already set for the member or the office wins, and then neither is added; a `CLAUDE_CODE_ARTIFACT` variable already set wins over the `0`.

`GET`, `PUT /api/office/enterprise`, `POST /api/office/enterprise/secret` and `POST /api/office/enterprise/check` return `{available,enabled,locked,connected,problem}`. `available` is false on Hosted, where the writes return 403 `hosted`. `locked` is true while the box is on and no secret was accepted; messages to agents (ask replies and edits too) and member adds then return 409 `enterprise_secret_needed`. Tell the member: an owner pastes the secret in Settings -> Enterprise. `connected` is null or `{company,kind,seats,inUse,offices,checkedAt}`; `problem` is null, `bad_secret`, `not_signed` or `unreachable`. A secret that the seat service refuses returns 403 `enterprise_secret_rejected` or `enterprise_not_signed`, 429 `enterprise_rate_limited` or 502 `enterprise_bad_request`; one it could not check returns 503 `enterprise_unreachable`; one with spaces, control characters or more than 512 characters returns 400 `invalid_secret`. Only an accepted secret replaces the stored one. Turning the box off frees the office's seats on the account and deletes the secret.
