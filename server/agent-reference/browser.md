# Desktop browser control

`POST /api/agents/:id/browser` controls a manager-offered desktop Chrome tab. The manager pairs Chrome in Integrations → Browser Use, offers a tab to one agent or All, and turns on Agent control. Other chat speakers do not change whose browser this is. Decline untrusted pages. Confirm the browser belongs to the manager before another member asks to use a login.

You can read an offered page before `goto`; `goto` navigates that same tab. Without an offered tab, ask the manager to turn on Agent control in the extension popup. Send `{action:"tabs"}` to list available targets as `{target,scope,browser,title,url}`. `url` is the page's last committed URL; `title` is the one Chrome reported at the offer and is empty once the page commits elsewhere. A target on a refused office page has empty `title` and `url` and `officePageRefused:true`. Offers from all paired browsers count together: an individual offer takes precedence, otherwise a sole All offer is used. Actions `snapshot`, `text`, and `screenshot` read the current tab. `goto` needs `url`; `click` needs `selector`; `fill` needs `selector,text`; `select` needs the `<select>` element's `selector`, which can be hidden under a styled control, and exactly one of `value` or `label`; `check` needs the `selector` of a checkbox, radio button or switch, also one under its own styled cover, and optional `checked` (default true); `press` needs `key` and optionally `selector`; `upload` needs one file-input `selector` and an absolute server `path`; `close` ends the grant. With several All grants, pass the returned `target` on each call. Target selection is not sticky.

Reads include child-frame labels and `framePath`; pass that path for frame actions. Paths index the current child frames, outer to inner, so read again after a page or frame change. Frame actions need one strict element `selector`; `press` in a frame requires a selector. Reads share a 20,000-character budget and include up to 64 frames through eight child levels.

For long feeds, `snapshot` and `text` accept an optional `selector` and/or `framePath`, for example `{"action":"snapshot","selector":"role=dialog"}` or `{"action":"text","framePath":[0],"selector":"article >> nth=20"}`. A scoped read returns one strict element in one frame, without child-frame sections. The default element is body and the default frame is the main frame. A snapshot marks a checked control `[checked]`; an unchecked one has no mark. Snapshots include a rendered-text supplement for visible editable textboxes when ARIA omits their text, within the same 20,000-character read budget. A snapshot shows a password field's value as `[password masked]`.

Semantic selectors use Playwright syntax: `role=dialog >> role=button[name=/^Post$/]`. Use `[name="Post"]` for a name or `[name=/^Post$/]` for an exact name; `[exact=true]` is unsupported. CSS `[role="button"]` matches only explicit role attributes, not every semantic button. Known selector syntax errors, and a selector that matches several elements, return `invalid_request` with fixed guidance. Upload accepts one regular non-sensitive file up to 4 MiB, replaces that input's file selection, and does not submit a form. Inspect after upload because selection can start a site upload.

A `click` returns ok when Chrome dispatched it at the element's position after the element passed Playwright's checks. This does not prove that the page applied it, so take a snapshot when the outcome matters. A successful click that closes its popup reports the selected parent page. A popup close before mouse release can return `action_failed`. If the element never becomes clickable, `click` returns `action_failed` with the reason, and no input was sent. A `check` on a control already in that state sends no input. Otherwise it clicks the control's centre. The element there must belong to the control: the control, or an element inside it or inside a label or parent that wraps only this control. Another element there, a disabled control, or a centre outside the viewport returns `action_failed`, and no input was sent. A click that does not change the state also returns `action_failed`. A `click`, `select` or `check` waits for a navigation that it starts; if that page has not loaded by the deadline, the result adds `loading:true`. JavaScript dialogs are dismissed and `beforeunload` is accepted. The result lists the dialogs that its action opened; a failure lists them in `error.dialogs`. Add `"dialog":"accept"` to a `click`, `press`, `select` or `check` to accept the first dialog that the action opens; later dialogs are dismissed. A dialog that opened while no action ran is dismissed when the next action starts, and that action lists it.

An offered tab acts as your manager on every site where their Chrome is signed in. A tab they offered on an Isomux office lets you use that office as them. Browser control refuses any other Isomux office page: a `goto`, click or redirect that reaches one returns 403 `office_page_refused` with no page data, and other actions on it are refused at once. Use `goto` to leave it. To use that page, the manager offers a tab that shows it; when that tab already shows as offered (a link opened it from the offered tab, or the offered tab moved there), they turn Agent control off and on again. A new offer has a new target, and a call that names the old one returns `browser_control_ended`.

Only HTTP(S) URLs without URL credentials are accepted. Desktop localhost is the member's computer; use `preview-url` for a server-local page. A connection loss or `action_timeout` can leave side effects unknown, so inspect before retrying. A read or `goto` on a page that does not answer within 5 s returns `action_failed`: try once more, then use another tab. The bridge never replays commands. If an app-launch link makes Chrome detach its debugger while the same tab and page target survive, the extension can recover once within three seconds. An interrupted action returns `action_failed` with an unknown outcome; inspect the page before retrying. New actions wait within that bound, and failed recovery ends control. Actions on one grant are serialized across agents; while one settles, later actions return `action_timeout` and are not sent. An action that does not settle ends within about a minute, so do not re-offer the tab for a timeout. On an All grant, `close` ends access for every agent. An offer expires when the manager chose (Never by default, or 15 minutes, 1 hour, or 4 hours); agent actions do not extend it. The extension uses the desktop viewport. After a connection loss, such as an office restart, the extension offers the same tabs again when it reconnects, with the same targets; until then actions return `browser_offline`. Pages that a site opened from the tab are not offered again, and an action in flight at the loss has an unknown outcome. An extension reload or a Chrome restart releases offers, and the manager must offer the tab again. When `tabs` returns `outdatedBrowsers`, those browsers run an out-of-date extension, which may not offer tabs again after a restart: ask the manager to update it instead of waiting. Errors include `invalid_request`, `action_failed`, `action_timeout`, `browser_not_paired`, `browser_offline`, `browser_target_required`, `browser_control_ended`, and `office_page_refused`; ask the member to pair or reconnect when needed.

Safe example: `POST /api/agents/:id/browser` with `{"action":"snapshot"}`.

## Route contract

`POST /api/agents/:id/browser` accepts the action bodies above. Successful reads/actions return `{url,title,target,...}`; `screenshot` also adds a file card, `upload` adds `uploaded:{name,mimeType,size}`, `select` adds `selected` (the selected values), `check` adds `checked` (the state after the action), an input whose navigation did not load adds `loading:true`, an action that opened JavaScript dialogs adds `dialogs:[{type,message,accepted}]`, and `close` confirms closure. `tabs` returns `{tabs,outdatedBrowsers?}`. Every agent, including a privileged agent, can target only itself. A different target returns 403, and so does an Isomux office page that the manager did not offer (`office_page_refused`). Invalid actions return 400/422, absent control returns 409, and bridge failures return structured errors named above.
