# Desktop browser control

`POST /api/agents/:id/browser` controls an offered desktop Chrome tab. A member pairs Chrome in Integrations → Browser Use, chooses which agents may use that browser (My agents, My agents and members I pick, or All agents: every agent in a room they can access), and turns on Use this tab. Other chat speakers do not change whose browser this is. Decline untrusted pages. Confirm whose browser it is before another member asks to use a login.

You can read an offered page before `goto`; `goto` navigates that same tab. Without an offered tab, open your own: `{action:"open",url}` makes a new tab in your manager's browser when they turned on "Open their own tabs" in the extension popup, then runs `goto` on it. Only you see and use the tabs you open; you may hold several. Pass `browser` (an id or a name from `agentTabBrowsers`) to choose among several browsers, or to use another member's browser that lets your agents open tabs: `open` uses another member's browser only when you name it. Close each opened tab when you no longer need it. On `agent_tabs_off`, give the member the choice in your ask: turn on Open their own tabs, offer you a tab, or do the steps themselves. A member who runs agents under other accounts can pick those accounts under Agents. Send `{action:"tabs"}` to list available targets as `{target,scope,browser,member,title,url}`; `member` names whose browser it is. `tabs` also lists `agentTabBrowsers:[{id,browser,member}]`, the online browsers where you may open a tab. A tab you opened has scope `{kind:"opened",agentId,via}`. `url` is the page's last committed URL; `title` is the one Chrome reported at the offer and is empty once the page commits elsewhere. A target on a refused office page has empty `title` and `url` and `officePageRefused:true`. Without a `target`, your own tab is used (a tab you opened), otherwise a sole offer from your manager's browsers, otherwise a sole offer of another member. When you hold two tabs of your own, pass `target`. Actions `snapshot`, `text`, and `screenshot` read the current tab. `goto` needs `url`; `click` needs `selector`; `fill` needs `selector,text`; `select` needs the `<select>` element's `selector`, which can be hidden under a styled control, and exactly one of `value` or `label`; `check` needs the `selector` of a checkbox, radio button or switch, also one under its own styled cover, and optional `checked` (default true); `press` needs `key` and optionally `selector`; `upload` needs one file-input `selector` and an absolute server `path`; `mute` mutes the tab (`muted:false` unmutes; tabs you open start muted); `close` ends the grant, and closes a tab you opened. When several offers tie, pass the returned `target` on each call. Target selection is not sticky.

Reads include child-frame labels and `framePath`; pass that path for frame actions. Paths index the current child frames, outer to inner, so read again after a page or frame change. Frame actions need one strict element `selector`; `press` in a frame requires a selector. Reads share a 20,000-character budget and include up to 64 frames through eight child levels.

For long feeds, `snapshot` and `text` accept an optional `selector` and/or `framePath`, for example `{"action":"snapshot","selector":"role=dialog"}` or `{"action":"text","framePath":[0],"selector":"article >> nth=20"}`. A scoped read returns one strict element in one frame, without child-frame sections. The default element is body and the default frame is the main frame. A snapshot marks a checked control `[checked]`; an unchecked one has no mark. Snapshots include a rendered-text supplement for visible editable textboxes when ARIA omits their text, within the same 20,000-character read budget. A snapshot shows a password field's value as `[password masked]`. Text that the page hides with `aria-hidden`, often after a dialog, gives a note in place of the snapshot; `role=` selectors do not match it either, so use `text` and CSS selectors.

Semantic selectors use Playwright syntax: `role=dialog >> role=button[name=/^Post$/]`. Use `[name="Post"]` for a name or `[name=/^Post$/]` for an exact name; `[exact=true]` is unsupported. CSS `[role="button"]` matches only explicit role attributes, not every semantic button. Known selector syntax errors, and a selector that matches several elements, return `invalid_request` with fixed guidance. A `text` or `snapshot` whose selector matches nothing within 3 s returns `action_failed`. Upload accepts one regular non-sensitive file up to 4 MiB, replaces that input's file selection, and does not submit a form. Inspect after upload because selection can start a site upload.

A `click` returns ok when Chrome dispatched it at the element's position after the element passed Playwright's checks. This does not prove that the page applied it, so take a snapshot when the outcome matters. A `click`, `select` or `check` waits for a navigation that it starts; if that page has not loaded by the deadline, the result adds `loading:true`. During an action, JavaScript dialogs are dismissed and `beforeunload` is accepted. The result lists the dialogs that its action opened; a failure lists them in `error.dialogs`. Add `"dialog":"accept"` to a `click`, `press`, `select` or `check` to accept the first dialog that the action opens; later dialogs are dismissed. A dialog that opens while no action runs stays open for the member: until they answer it, each action fails at once and lists it in `error.dialogs`.

An offered tab acts as the member who offered it on every site where their Chrome is signed in. A tab you opened acts as the member whose browser it is. A tab they offered on an Isomux office lets you use that office as them; a tab you opened refuses every office page, and `open` refuses an office URL before it makes a tab. Browser control refuses any other Isomux office page: a `goto`, click or redirect that reaches one returns 403 `office_page_refused` with no page data, and other actions on it are refused at once. Use `goto` to leave it. Isomux apps are not office pages: open one by its direct `url`, not its `shortUrl`, which is an office page. You act there as the member who offered the tab.

Only HTTP(S) URLs without URL credentials are accepted. Desktop localhost is the member's computer; use `preview-url` for a server-local page. A connection loss or `action_timeout` can leave side effects unknown, so inspect before retrying. On an offered tab that is not your own, `close` ends the offer for every agent. An offer lasts until the member turns it off. The extension uses the desktop viewport. Errors include `invalid_request`, `action_failed`, `action_timeout`, `browser_not_paired`, `browser_offline`, `browser_target_required`, `browser_control_ended`, `office_page_refused` and `agent_tabs_off`; ask the member to pair or reconnect when needed. When an action fails or times out, a click or `check` returns `action_failed`, an office page is refused, or a tab or browser goes away, fetch the `browser-failures` page.

Safe example: `POST /api/agents/:id/browser` with `{"action":"snapshot"}`.

## Route contract

`POST /api/agents/:id/browser` accepts the action bodies above. Successful reads/actions return `{url,title,target,...}`; `screenshot` also adds a file card, `upload` adds `uploaded:{name,mimeType,size}`, `select` adds `selected` (the selected values), `check` adds `checked` (the state after the action), `mute` adds `muted`, an input whose navigation did not load adds `loading:true`, an action that opened JavaScript dialogs adds `dialogs:[{type,message,accepted}]`, and `close` confirms closure. `open` returns the `goto` result with `target`, `browser` and `member`; a `goto` that fails closes the new tab and returns its error. `tabs` returns `{tabs,outdatedBrowsers?,agentTabBrowsers?}`. Every agent, including a privileged agent, can target only itself. A different target returns 403, and so does an Isomux office page that the member who offered the tab did not offer (`office_page_refused`). Invalid actions return 400/422, absent control and `agent_tabs_off` return 409, and bridge failures return structured errors named above.
