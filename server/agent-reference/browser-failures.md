# Browser failures

Part of the `browser` page: why a browser action fails, and what happens to tabs and offers when a connection, the extension or Chrome goes away.

A successful click that closes its popup reports the selected parent page. A popup close before mouse release can return `action_failed`. If the element never becomes clickable, `click` returns `action_failed` with the reason, and no input was sent. A `check` on a control already in that state sends no input. Otherwise it clicks the control's centre. The element there must belong to the control: the control, or an element inside it or inside a label or parent that wraps only this control. Another element there, a disabled control, or a centre outside the viewport returns `action_failed`, and no input was sent. A click that does not change the state within 3 s also returns `action_failed`.

A read or `goto` on a page that does not answer within 5 s returns `action_failed`: try once more, then use another tab. The bridge never replays commands. If an app-launch link makes Chrome detach its debugger while the same tab and page target survive, the extension can recover once within three seconds. An interrupted action returns `action_failed` with an unknown outcome; inspect the page before retrying. New actions wait within that bound, and failed recovery ends control. Actions on one grant are serialized across agents; while one settles, later actions return `action_timeout` and are not sent. An action that does not settle ends within about a minute, so do not re-offer the tab for a timeout. When the member narrows Agents, the agents it leaves out lose its tabs at once. After a connection loss, such as an office restart, the extension offers the same tabs again when it reconnects, with the same targets; until then actions return `browser_offline`. The error names the browser that holds the tab, also another member's. After an office restart, a target whose browser has not reconnected yet can return `browser_control_ended`. Pages that a site opened from the tab are not offered again, and an action in flight at the loss has an unknown outcome. A tab you opened also comes back after a connection loss; when its browser is offline, `open` uses another one. An extension reload or a Chrome restart releases offers and the tabs you opened: the member must offer the tab again, or you open a new one. A member who turns off "Open their own tabs" ends your control of the tabs you opened. A tab you opened whose control ends without your `close` stays open as the member's tab, and you cannot use it again. When `tabs` returns `outdatedBrowsers`, those browsers run an out-of-date extension, which may not offer tabs again after a restart. The `browser_offline` and `browser_control_ended` errors say for each one whether to ask the manager to update it or the Chrome Web Store updates it.

After `office_page_refused`, to use that page the member offers a tab that shows it; when that tab already shows as offered (a link opened it from the offered tab, or the offered tab moved there), they turn Use this tab off and on again. A new offer has a new target, and a call that names the old one returns `browser_control_ended`. When a refused redirect leaves the tab on its page, actions there work again.
