# Asks

An ask is what you need from one member to get unblocked: a decision, an answer, or an action only they can take. It stays above the chat input for that member and in their Inbox, with a reply field, until they answer it. Keep the prompt to what the member must decide or do and your pick, in one or two short sentences. Put what you did and how things work in the chat, not in the ask. Open one instead of asking again in later messages: the member still sees it, so you do not need to repeat it.

Open one with `POST /api/agents/:id/asks`, where `:id` is your own agent id. Send the prompt as a text/plain body, up to 4000 characters. It goes to your manager; to send it to another member who can reach your room, add `member=<username>` to the query. With a quoted heredoc, nothing needs escaping:

```
curl -s -X POST "<office>/api/agents/<your-id>/asks" -H "<authorization>" -H 'Content-Type: text/plain' --data-binary @- <<'EOF'
Pull a per-agent spend breakdown before we change models?
EOF
```

A JSON body (`Content-Type: application/json`) takes `text` (or `prompt`), `member`, `link`, `step`, `options`, `recommended`, `priority`, `commands`, `editFiles` and `readFiles`. Query parameters work only with a text/plain body.

When the member must do an Integrations step, send `step` instead of `link` (see the connections page): the ask then closes itself when the step is done. For any other office page, add `link=<page>` to the query (or `link` in a JSON body). The ask card then has a button that opens that page. The value is an office page name in path form, not a URL: `/tasks`, `/automations`, `/apps`, `/skills`, `/integrations`, `/settings`, `/inbox/pages`, `/inbox/asks`, or an Integrations tab: `/integrations/providers` (Claude and Codex sign-in), `/integrations/mcp`, `/integrations/secrets`, `/integrations/variables`, `/integrations/voice` (mic and read aloud), `/integrations/browser` (Chrome pairing), `/integrations/github` (a room's GitHub issue link; it opens only for an owner, and a member lands on the default tab), `/integrations/pager` (where the member's pages go), `/integrations/api-tokens`. Each of these paths on the office's web address also opens its page as a plain link. When the member must act in another agent's chat, set `link` to `/agents/<agentId>`: the button opens that agent's chat. The member must be able to reach the agent's room.

When the answer is one of a few choices, or you recommend an answer, add 2 to 10 options, one `option=<text>` each in the query (or `options` in a JSON body). Each is at most 80 characters, and they must differ. The card shows a button for each. A tap puts that option in the reply field, and the member can edit it before sending. Mark the answer you recommend with `recommended=<option text>` (or `recommended` in a JSON body): the card marks that option and the reply field starts with it. Without a recommendation the field starts empty; an ask without options starts with "done". A secret request has no options.

To mark how urgent an ask is, add `priority=<level>` (or `priority` in a JSON body), from `P0` (most urgent) to `P4`, as on the task board.

An ask can carry chat affordances, at most 10 in total: `commands` for the member's terminal panel (as terminal-command), `editFiles` to open in the editor (as edit-file) and `readFiles` to show in the card (as read-file). Paths resolve against your cwd, and a read file is copied when you create or edit the ask. A video or audio file is not copied and has no size limit: the card plays it from its path, so keep it there until the member answers. In the query, add one `command=`, `editFile=` or `readFile=` per item, percent-encoded with `%20` for a space, since a `+` stays a plus. A command is easier in a JSON body:

```
curl -s -X POST "<office>/api/agents/<your-id>/asks" -H "<authorization>" -H 'Content-Type: application/json' --data-binary @- <<'EOF'
{"text": "Delete the merged branches t-a and t-b?", "commands": ["git branch -D t-a t-b && git push origin --delete t-a t-b"]}
EOF
```

The ask returns the resolved forms: `editFiles` as `{cwd, path}` and `readFiles` as the copies' `{filename, originalName, mediaType, size}`, with `path` added for a video or audio file shown from its path. A secret request has none.

The answer arrives as a normal message from the member, starting with `[Reply to your ask <id>: "<prompt>"]`. If the member dismisses it, the bracket says `Dismissed your ask` and the message is `Dismissed` or the reason the member typed. If the member files it as a task for later, the bracket says `Your ask <id> is now task <taskId>`: go on without an answer, do not ask again, and do not start the task until someone assigns it. In each case the ask closes.

An app whose message target you are can open asks in your name (`apps` reference). Such an ask has `app: {name, createdAt}`, and you can manage it like your own. Its answer names the app: `[Reply to app <name>'s ask <id>: "<prompt>"]`, and the same for a dismiss or a filed task. Act on it for the app.

A member message that starts with `About your ask "<the start of your question>":` (or the same in the member's language) is a question about that open ask, not its answer. Answer it in the chat and keep the ask open; edit the ask if your answer changes it.

`GET /api/agents/:id/asks/:askId` returns the ask, open or closed. `GET /api/agents/:id/asks` lists your open ones. Change the prompt with `PATCH /api/agents/:id/asks/:askId` and a text/plain body. The edit keeps the link unless you send a new `link=` value to change it or `link=` to remove it. In the same way, `option=` values replace the options, and a single empty `option=` (or `options: []`) removes them; `commands`, `editFiles` and `readFiles` work the same way. The recommendation goes with the options: new options without `recommended` have none, and removing the options removes it. To change only the recommendation, send `recommended` alone; `recommended=` removes it. The edit keeps the priority unless you send a new one; `priority=` (or `priority: null`) removes it. When the question no longer applies, for example because the member answered in the chat, delete it with `DELETE /api/agents/:id/asks/:askId`. You can have 50 open at a time. You can manage only your own asks.

A secret request (see the connections page) is also one of your asks. It has `secret: {requestId, kind?, scope, name, hosts, form, reason, app?, url?, secret?, oauth?, ownerUserId?, answerUserId?}`, and its prompt is the reason. `kind` is `variable` or `mcp-server` for those requests, and absent for a secret. The member answers it in its masked form, not with a reply. You cannot edit it, but you can delete it to withdraw the request. An office secret request has no `memberUserId`. It goes to the office owner in `answerUserId`, who is its `member`; without one it goes to every office owner, and `member` is null.

Closed asks are kept. `GET /api/agents/:id/asks/history` lists an agent's closed asks, newest first: your own, or those of any agent whose logs you can read (see the conversation-history page). Add `member=<username>` for the asks for one member and `limit` (1 to 200, default 50). For the next page, send the response's `nextBefore` as `before`. To read another agent's ask, use this list: the route by id is for your own asks.

A closed ask has `closed: {at, outcome, by, answer?, taskId?}`. `outcome` is `replied`, `dismissed`, `filed`, or for a secret request `saved` or `declined`, when a member answered; `withdrawn` when the agent, or the app that opened it, deleted the ask; `done` when its step was done; `agent_removed` when the agent was removed. `by` is the member who answered, or null. `answer` is their words as the agent got them, and `taskId` the filed task.

Safe example: `GET /api/agents/<your-id>/asks`.

## Route contract

| Method and route                     | Request                                                                                                                                                                                                              | Success                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `POST /api/agents/:id/asks`          | text/plain prompt, query `member`, `link`, `option`, `recommended`, `priority`, `command`, `editFile`, `readFile`; or `{text\|prompt,member?,link?,options?,recommended?,priority?,commands?,editFiles?,readFiles?}` | `201` ask                    |
| `GET /api/agents/:id/asks`           | None                                                                                                                                                                                                                 | Your open asks, oldest first |
| `GET /api/agents/:id/asks/history`   | Query `member`, `before`, `limit`                                                                                                                                                                                    | `{asks, nextBefore}`         |
| `GET /api/agents/:id/asks/:askId`    | None                                                                                                                                                                                                                 | The ask                      |
| `PATCH /api/agents/:id/asks/:askId`  | text/plain prompt, query `link`, `option`, `recommended`, `priority`, `command`, `editFile`, `readFile`; or `{text\|prompt,link?,options?,recommended?,priority?,commands?,editFiles?,readFiles?}`                   | The ask                      |
| `DELETE /api/agents/:id/asks/:askId` | None                                                                                                                                                                                                                 | `204`                        |

An ask is `{id, agentId, memberUserId, member, prompt, createdAt, updatedAt, link?, step?, options?, recommended?, priority?, commands?, editFiles?, readFiles?, secret?, app?}`. A step ask's `step` and `link` are fixed: an edit that sends either returns 400. A closed id returns 404 on an edit or delete, and an unknown id on every route. An `:id` other than your own returns 403; on the history route, an agent whose logs you cannot read. On the history route, an unknown `member` returns 422 `unknown_member`, and a bad `before` or `limit`, or another query parameter, returns 400 `invalid_query`. An empty or too long prompt, or both `text` and `prompt`, returns 400. An unknown `member`, or a member who cannot reach your room, returns 422. With no `member`, an agent without a manager gets 409. A `link` that is not one of the pages above, or names an agent that does not exist or whose room the member cannot reach, returns 422 `invalid_link`. Options that break the rules above, or a `recommended` that is not one of the options, return 422 `invalid_options`. A `priority` that is not `P0` to `P4` returns 422 `invalid_priority`. A bad command or path returns 422 `invalid_command`, `invalid_edit_file` or `invalid_read_file`, and a credential store path 403 `forbidden_path`. A list that is not strings, an empty list on create, or more than 10 in total returns 422 `invalid_affordances`. A refused create or edit changes nothing. More than 50 open asks returns 429. An edit of a secret request returns 409 `secret_request`.
