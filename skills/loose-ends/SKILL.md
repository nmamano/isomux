# Loose Ends

Review the conversation and the work you changed or dispatched. Check live state, not only the conversation: uncommitted or unpushed changes, worktrees, running jobs and CI, scheduled messages, the agents you dispatched, and the tasks you claimed or filed. When live state contradicts the conversation, report the live state. Mark what you could not check as unchecked.

A loose end is something that still needs an action by an agent or a human. Report only those, in two groups:

1. **Needs you.** Actions only the member can do. For each one, your recommendation and what it unblocks.
2. **In flight.** Work that runs now or waits on someone else: who has it, and what happens when it lands.

Each "Needs you" item is also an ask for the member (see the asks reference page). First list your open asks: open an ask only for an item that is not one yet, and delete your asks that are done or no longer needed. In-flight items stay in the recap and never become asks.

Then add a **Done this session** section: what is closed so far, one line each, in plain product language.

For each loose end, propose one concrete next action, such as creating an Isomux task, recording a fact in memory or a project document, committing, or verifying. Ask before an action that needs member approval.

If you also want to tell the member something that needs no action, put it under the heading "Informative only, not actionable". Do not invent items for that heading.

If nothing remains, say so in one line. Do not end the session or start new work.
